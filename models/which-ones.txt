MM Tools model downloader and inventory
=======================================

`download_models.py` resolves `MODELS` from its own tracked location, so it can
be launched from any working directory and still targets `<mm-tools>/models`.
Before every selected download it explicitly creates the complete destination
with `parents=True`. A fresh clone therefore does not need pre-existing `qwen`,
`text-only`, `imports`, project-local checkpoint, Comfy model,
`redesign/weights`, or PaddleX directories.
Current Hugging Face Hub writes real files into `local_dir`; older Hub releases
receive their former `local_dir_use_symlinks=False` compatibility flag only
when that argument still exists.

Create the small downloader environment once:

```bash
cd ~/multimedia/models
uv venv --python 3.12 --seed --managed-python .venv
source .venv/bin/activate
uv pip install -U huggingface_hub hf_transfer
```

Interactive mode asks for the snapshot file-worker count first, then presents the
bundle selection. Press Enter at the selection prompt to retain the original
behavior and download everything:

```bash
uv run download_models.py
```

The same choices work non-interactively by number or name:

```bash
uv run download_models.py --list
uv run download_models.py 2,6,10 --workers 24
uv run download_models.py minimax stableaudio yue2
uv run download_models.py all --yes --workers 24
```

Bundle selection numbers are deliberately separate from the stable inventory
identifiers below. Each bundle includes every downloadable artifact needed by
that runtime. Inventory identifiers 22-23 are retired rather than renumbered,
so older notes keep their meaning.

The inventory mirrors all 62 active artifact definitions in the downloader,
numbered through 63 because 22-23 are intentionally reserved. Trees show
files or major component directories expected from a fresh run; an ellipsis
means the remainder of that approved snapshot subset is retained in the same
folder. Every new artifact is pinned to an immutable Hub revision. Model use
remains governed by each upstream model license and access agreement.
