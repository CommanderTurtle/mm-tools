MM Tools model downloader and inventory
=======================================

`download_models.py` resolves `MODELS` from its own tracked location, so it can
be launched from any working directory and still targets `<mm-tools>/models`.
Before every selected download it explicitly creates the complete destination
with `parents=True`. A fresh checkout therefore does not need pre-existing `qwen`,
`text-only`, `imports`, project-local checkpoint, Comfy model,
`visual-modeling/redesign/weights`, or PaddleX directories.
Current Hugging Face Hub writes real files into `local_dir`; older Hub releases
receive their former `local_dir_use_symlinks=False` compatibility flag only
when that argument still exists.

Store bytes live only under `models/<org>--<model>/` directories. Runtime
paths shown below (project-named folders such as `qwen/`, `hynomas/`, and
`scenebloom/`) are the paths the projects consume: the first run migrates any
legacy copies into the canonical directories and leaves compatibility
symlinks behind, so this inventory keeps resolving exactly as written.

Create the small downloader environment once:

```bash
cd ~/multimedia/models
uv venv --python 3.12 --seed --managed-python .venv
source .venv/bin/activate
uv pip install -U huggingface_hub hf_transfer gdown==5.2.0
```

Interactive mode asks for the snapshot file-worker count first, then presents the
bundle selection. Press Enter at the selection prompt to retain the original
behavior and download everything:

```bash
uv run download_models.py
```

The same choices work non-interactively by number or name:

```bash
uv run download_models.py --list
uv run download_models.py 2,6,10 --workers 24
uv run download_models.py minimax stableaudio yue2
uv run download_models.py all --yes --workers 24
```

Bundle selection numbers are deliberately separate from the stable inventory
identifiers below. Each bundle includes every downloadable artifact needed by
that runtime. Canonical snapshots always land under `models/<lane>/
<org--model>/`; the traditional runtime folders (lane `weights/`,
`pretrained/`, `checkpoints/`, `models/` trees) are recreated by the
downloader as relative symlinks to those snapshots, so runtimes never patch
their paths and nothing occupies disk twice. Inventory identifiers 22-23 are
retired rather than renumbered,
so older notes keep their meaning. Former bundles 21 (animate) and 24 (ltx)
are retired as well: those weights now come from the standalone
workflows/download_models.py, documented in the workflows section at the end
of this file.

The inventory mirrors every active artifact definition in the downloader,
numbered 1 through 105 (plus 43a retired) with 22-23 intentionally reserved.
Trees show files or major component directories expected from a fresh run; an ellipsis
means the remainder of that approved snapshot subset is retained in the same
folder. Every new artifact is pinned to an immutable Hub revision, except the
ungated comfyicu LTX-2.5 mirror, whose re-committed files track main without a
pin. Model use remains governed by each upstream model license and access
agreement.

```text

├── diffusion_models/
│   ├── ideogram4_int8_convrot.safetensors            (main model)
│   └── ideogram4_unconditional_nvfp4_mixed.safetensors (CFG unconditional)

```

Per Kijai (Comfy-Org/Ideogram-4 discussion 1): both the main and the
unconditional model are meant to load together; running main-only loses
quality most of the time, while the unconditional side tolerates the nvfp4
quantization because its quality is not critical. Sampling follows the
corrected template: CFG override starting at 0.7 with plain euler.
No access grants or hf auth login are required for any of these files.
