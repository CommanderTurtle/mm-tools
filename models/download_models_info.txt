MM Tools model downloader
=========================

Create one small uv environment in this directory and install the current
Hugging Face Hub client, mm-tools' canonical hf_transfer backend and the PHC
Drive downloader:

  cd ~/multimedia/models
  uv venv --python 3.12.10 --seed --managed-python .venv
  source .venv/bin/activate
  uv pip install -U huggingface_hub hf_transfer gdown==5.2.0
  uv run download_models.py --list
  uv run download_models.py

## NOTE: Workers == synonymous with "cpu cores". 16=safe worker count for Intel Ultra 9 285k. This downloader greatly improves HF download speed, utilizing the hf_transfer package.

The first interactive question sets the parallel snapshot file workers.
The next prompt selects numbered project bundles; Enter preserves the original
"all" behavior. Every selected bundle that offers model tiers (`lingbot`,
`ming3`, `underdog`) then re-prompts with per-tier sizes, the disk-hungry
choices, and a 5090-oriented recommendation; answers are comma-separated,
`a` selects every tier, and Enter accepts the marked default (`lingbot` = 5,
Q8_0 GGUF; the ~74 GB native tier 1 repo only comes with an explicit
`lingbot:1` — typed with the selection it also skips that bundle's prompt).
Examples:

  uv run download_models.py 4d lingbot:1 fire3d --workers 24
  uv run download_models.py aukspeech sculpting worldsculpt
  uv run download_models.py v2v
  # The former animate/ltx bundles now live in the standalone workflow
  # downloader (workflows/README.md):
  cd ../workflows && .venv/bin/python download_models.py ltx animate
  uv run download_models.py nvidia-sim
  uv run download_models.py yue2
  uv run download_models.py all --yes --workers 24
  uv run download_models.py --audit

`--audit` inventories the installed store without downloading: it prints each
bundle's bytes on disk plus every artifact path it still needs (missing
snapshot roots and direct-release SHA-256 mismatches), suggests the exact
selection command for the next run, then refreshes `models/hashes.txt` — a
plaintext SHA-256 registry covering only model files claimed by bundle
definitions, so junk never enters it and dropped files fall out as stale;
untouched size/mtime signatures skip rehashing, and hashing uses the same
worker count as downloads. The final cleanup pass lists files and folders
under `models/` claimed by no artifact definition — unknown top-level
folders, stray files, and files outside any allowlist inside known
snapshots — with sizes, and always prompts before deleting (`y` all, `e`
per entry, Enter keeps; `--prune` deletes unattended). Hub cache bookkeeping
(blobs, refs, `models--*`, `.cache`, marker files) and the downloader's own
code files are never flagged; symlinked lane paths are skipped entirely.

Every newly introduced upstream snapshot is pinned to the immutable revision
audited for this source import. File allowlists retain only runtime-required
weights, configs, tokenizers, model code, manifests, and legal notices. The
script does not create project environments and it never deletes older files.
Hugging Face's local snapshot metadata makes interrupted transfers resumable:
rerun the same selection.

Most artifacts download directly into the path consumed by their project.
Shared Comfy assets first land under `models/imports`, preserving resumable
snapshot state, and are then exposed in `workflows/ComfyUI/models` by same-filesystem
hard links. A copy is used only when the two paths reside on different
filesystems. Existing different files are never overwritten.

The sculpting bundles also install five pinned, allowlisted dependencies that
the upstream pipeline JSON otherwise resolves online: TRELLIS-image-large's
single required sparse decoder, DINOv3 ViT-L/16, the official ungated
ZhengPeng7 BiRefNet checkpoint, MoGe-2 camera
calibration, and NAF feature upsampling. The legacy
decoder is hard-linked into TRELLIS.2-4B; both sculpting adapters point their
generated local pipeline config at the shared DINO/BiRefNet directories.
Direct-release assets use resumable partial downloads and SHA-256 verification,
with exact byte sizes where recorded. Snapshots always save under
`models/<lane>/<org--model>/`; the downloader recreates the traditional
runtime folders (lane `weights/`, `pretrained/`, `checkpoints/`, `models/`)
as relative symlinks onto those snapshots. The current artifact list is
maintained in `which-ones.txt`.

`lingbot` is the 14B world-model program in six tiers: the official native
14B causal-fast package for the studio (tier 1, linked into the lane folder),
realrebelai GGUF quants Q4_K_S through Q8_0 for the bundled ComfyUI Rebels
nodes (tiers 2-5, from 8 GB VRAM upward), and the igorls hybrid-NVFP4 export
with the official diffusers base for SGLang serving on 72 GB+ Blackwell
(tier 6). Tier 5 (Q8_0) is the default for non-interactive selection and the
marked recommendation on a 32 GB RTX 5090; tier 1's complete ~74 GB repository
is fetched only by an explicit `lingbot:1`.
Everything lands under `models/lingbot/<org--model>/`; see the 43
entry in `which-ones.txt`. The retired 1.3B single-5090 bundle is gone; the
FastFrames lane keeps its own 1.3B checkpoints.

`nvidia-sim` uses the pinned, ungated
`voxta/Llama-3-8B-LLM2Vec-ARDY-INT8` snapshot. It is the complete ARDY text
encoder after both McGill LLM2Vec adapters are merged and the final weights
are quantized. This avoids the gated 16-bit base and runtime adapter merge;
it does not alter `snapshot_download` or its resumable local metadata.
The 4DAnyone neutral SMPL-X body model has separate upstream terms and must be
obtained manually; the downloader intentionally does not redistribute it.

`hf_transfer` is the canonical companion package in mm-tools setup commands.
The downloader leaves transport negotiation to the installed Hub client so it
does not inject version-specific backend flags or warnings.
Selecting `translate` retains the existing safe migration from the historical
`text-only/anhbn--raX-Translator-V1.0-GGUF` directory to its canonical name.

See `which-ones.txt` for the exact artifact inventory, paths, manual gates,
shared placements, and exclusions. Downloading a model binds the downloader
to that repository's license and access terms. Model artifacts are not part
of this AGPLv3 source tree.

For further example of hf_transfer, see the below example script:

```python
import os
# Enable hf_transfer for high-speed downloads
os.environ["HF_HUB_ENABLE_HF_TRANSFER"] = "1"
# Optional: Tune Tokio worker threads for your CPU cores
os.environ["TOKIO_WORKER_THREADS"] = "16"

from huggingface_hub import snapshot_download, logging

# Enable maximum verbosity logging
logging.set_verbosity_debug()

# Download first entire model repository
snapshot_download(
    repo_id="orcarouter/Qwen3.8-27B-Uncensored-NVFP4",
    local_dir="D:/Comfy/git clones/orcarouter--Qwen3.8-27B-Uncensored-NVFP4",
    local_dir_use_symlinks=False,  # Copy files instead of symlinks
    ignore_patterns=["*.gguf"]  # Showcase of ignorelist with wildcard
)

snapshot_download(
    repo_id="DavidAU/Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-NEO-CODER-MAX-MTP-GGUF",
    local_dir="D:/Comfy/git clones/DavidAU--Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-NEO-CODER-MAX-MTP-GGUF",
    local_dir_use_symlinks=False,  # Copy files instead of symlinks
    allow_patterns=["Qwen3.8-27B-TurboFCFusion-735-882-Here-Uncen-NEO-CODER-MAX-MTP-Q4_K_M.gguf"]
)
```

`uv run above-script.py` will download with those explicit instructions.

## Upstream notices

Notices for bundled upstreams are consolidated here.

- Budget3D and Idol SDK (bud3d, bud3d-turbo): permissive upstream terms for code and weights.
- SplatAnything / InfiniSplat (splat-v3): custom registration-based upstream terms for code and checkpoints.
- FastFrames (fastframes-live, fastframes-l): Apple sample-code terms for code, Apple research-only terms for the FastFrames checkpoints. LingBot World (bundled with fastframes-live): non-commercial attribution terms for code and DiT weights.
- Inworld Voice Isolator (inworld-isolator): permissive upstream terms for code and both checkpoints.
- Sophon Realtime (sophon-agent): permissive upstream terms for code and talker weights; the community NVFP4A16 thinker keeps the same terms.
- FAB and FAH (fab): permissive upstream terms for code; FAB and FAH model weights are research and non-commercial only. Third-party components: SAM-derived modules and MHR follow Meta research terms; pymomentum, DPVO, DROID-SLAM, TRAM and torchvision are permissive; Metric3D and RoMa carry attribution-style terms.
- Jeveration (jeveration): community research terms for the generator and decoders; Qwen and CLIP components are permissive; annotator and depth checkpoints carry research or non-commercial terms.
- BRIA RMBG-3.0 (bria-rmbg3): BRIA community terms; commercial use needs BRIA registration.
- WeMM-Video (wemm-video): Tencent community terms for code and AWQ weights; vLLM, SGLang and LAVIS overlay patches keep their own permissive upstream terms.
- Archive mirror (sHEL1562/shelling @ 4b859a1bfa801727c84087efd455f8c0a3205902, src/kr3ahardtofinds): exact copies of upstream files that are otherwise served only from GitHub releases, release archives or ad-hoc hosts — the NAF and AnyUp checkpoints, the MHR model plus MHR/GraphCMR body-map files (FAB, FlowHMR), the FAB studio demo clips, and the VBench scorer weights (fastframes-eval). Each file keeps its upstream licence; the pinned revision carries src/MANIFEST.sha256 as the integrity index, and the fetch/regeneration tooling lives beside the archive (fetch_src.sh, gen_files.py). Release-archive members are stored extracted (mhr_model.pt, raft-things.pth); no runtime path downloads zip archives.
