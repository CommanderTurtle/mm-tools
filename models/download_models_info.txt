MM Tools model downloader
=========================

Create one small uv environment in this directory and install the current
Hugging Face Hub client plus mm-tools' canonical hf_transfer backend:

  cd ~/multimedia/models
  uv venv --python 3.12.10 --seed --managed-python .venv
  source .venv/bin/activate
  uv pip install -U huggingface_hub hf_transfer
  uv run download_models.py --list
  uv run download_models.py

## NOTE: Workers == synonymous with "cpu cores". 16=safe worker count for Intel Ultra 9 285k. This downloader greatly improves HF download speed, utilizing the hf_transfer package.

The first interactive question sets the parallel snapshot file workers.
The next prompt selects numbered project bundles; Enter preserves the original
"all" behavior. Examples:

  uv run download_models.py 4d lingbot lingbot-5090 fire3d --workers 24
  uv run download_models.py aukspeech sculpting worldsculpt
  uv run download_models.py animate v2v
  uv run download_models.py nvidia-sim
  uv run download_models.py yue2
  uv run download_models.py all --yes --workers 24

Every newly introduced upstream snapshot is pinned to the immutable revision
audited for this source import. File allowlists retain only runtime-required
weights, configs, tokenizers, model code, manifests, and legal notices. The
script does not create project environments and it never deletes older files.
Hugging Face's local snapshot metadata makes interrupted transfers resumable:
rerun the same selection.

Most artifacts download directly into the path consumed by their project.
Shared Comfy assets first land under `models/imports`, preserving resumable
snapshot state, and are then exposed in `V2V/ComfyUI/models` by same-filesystem
hard links. A copy is used only when the two paths reside on different
filesystems. Existing different files are never overwritten.

The sculpting bundles also install five pinned, allowlisted dependencies that
the upstream pipeline JSON otherwise resolves online: TRELLIS-image-large's
single required sparse decoder, DINOv3 ViT-L/16, the official ungated
ZhengPeng7 BiRefNet checkpoint, MoGe-2 camera
calibration, and NAF feature upsampling. The legacy
decoder is hard-linked into TRELLIS.2-4B; both sculpting adapters point their
generated local pipeline config at the shared DINO/BiRefNet directories.
NAF is the sole direct-release asset: its partial download is resumable and is
accepted only after exact byte-size and SHA-256 verification.

`lingbot` contains only the 14B release's shared UMT5 encoder, tokenizer, and
Wan VAE. Its approximately 70 GB 14B DiT is intentionally not downloaded:
that model cannot run in the no-offload 32 GB workstation profile. Select
`lingbot-5090` alongside it for the official 1.3B causal-fast DiT used by the
local studio.

`nvidia-sim` uses the pinned, ungated
`voxta/Llama-3-8B-LLM2Vec-ARDY-INT8` snapshot. It is the complete ARDY text
encoder after both McGill LLM2Vec adapters are merged and the final weights
are quantized. This avoids the gated 16-bit base and runtime adapter merge;
it does not alter `snapshot_download` or its resumable local metadata.
The 4DAnyone neutral SMPL-X body model has separate upstream terms and must be
obtained manually; the downloader intentionally does not redistribute it.

`hf_transfer` is the canonical companion package in mm-tools setup commands.
The downloader leaves transport negotiation to the installed Hub client so it
does not inject version-specific backend flags or warnings.
Selecting `translate` retains the existing safe migration from the historical
`text-only/anhbn--raX-Translator-V1.0-GGUF` directory to its canonical name.

See `which-ones.txt` for the exact artifact inventory, paths, manual gates,
shared placements, and exclusions. Downloading a model binds the downloader
to that repository's license and access terms. Model artifacts are not part
of this AGPLv3 source tree.

For further example of hf_transfer, see the below example script:

```python
import os
# Enable hf_transfer for high-speed downloads
os.environ["HF_HUB_ENABLE_HF_TRANSFER"] = "1"
# Optional: Tune Tokio worker threads for your CPU cores
os.environ["TOKIO_WORKER_THREADS"] = "16"

from huggingface_hub import snapshot_download, logging

# Enable maximum verbosity logging
logging.set_verbosity_debug()

# Download first entire model repository
snapshot_download(
    repo_id="orcarouter/Qwen3.8-27B-Uncensored-NVFP4",
    local_dir="D:/Comfy/git clones/orcarouter--Qwen3.8-27B-Uncensored-NVFP4",
    local_dir_use_symlinks=False,  # Copy files instead of symlinks
    ignore_patterns=["*.gguf"]  # Showcase of ignorelist with wildcard
)

snapshot_download(
    repo_id="DavidAU/Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-NEO-CODER-MAX-MTP-GGUF",
    local_dir="D:/Comfy/git clones/DavidAU--Qwen3.8-27B-TURBO-Fable-Cold-Fusion-735-882-Heretic-Uncensored-NEO-CODER-MAX-MTP-GGUF",
    local_dir_use_symlinks=False,  # Copy files instead of symlinks
    allow_patterns=["Qwen3.8-27B-TurboFCFusion-735-882-Here-Uncen-NEO-CODER-MAX-MTP-Q4_K_M.gguf"]
)
```

`uv run above-script.py` will download with those explicit instructions.
